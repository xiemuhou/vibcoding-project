# 参考系统分析 — YSGB · Plan (10.10.166.131:3000)

## 一、系统概况

这是一套**生产计划管理系统**（YSGB · Plan），包含两个主要视图：

| 视图 | 功能 | URL 特征 |
|------|------|----------|
| 看板视图 | 每日生产计划排程、表格展示、验收实绩 | 主页面 |
| 数据看板 | 统计仪表盘、图表分析、效能评估 | `/生产一部/生产一部2026.html` |

---

## 二、技术栈分析

| 项 | 判断 | 依据 |
|----|------|------|
| 前端框架 | **Vue 3** | 页面左上角明确标注 `Vue 3` 徽章 |
| 运行端口 | 3000 | 通常为 Node.js (Express/Koa) 或 Vite dev server |
| 路由方式 | 文件路径式 | URL 为 `/生产一部/生产一部2026.html`，非 SPA hash 路由 |
| UI 组件库 | 可能为 Element Plus 或自研 | 表格、统计卡片、日期选择器风格接近 Element Plus |
| 图表库 | ECharts | 饼图、柱状图、混合图表的风格为典型 ECharts |
| 数据来源 | 后端 API 或 Excel 直读 | 页面显示"大样量(Excel)"字样，暗示部分数据来自 Excel |

**关键发现：URL 中出现 `.html` 后缀**

这说明系统可能采用了以下两种方案之一：
- **方案A**：纯静态页面 + 前端 JS 直接读取 Excel/JSON 文件（无后端数据库）
- **方案B**：多页应用(MPA)，每个部门/年份是独立的 HTML 入口，数据通过 API 获取

从"大样量(Excel)"标注和 `.html` URL 来看，**方案A 的可能性较大** — 即前端直接读取 Excel 文件作为数据源，而非通过数据库。

## 四、对 IP 管理系统的借鉴价值

### 4.1 可以借鉴的

| 设计元素 | 参考系统的实现 | IP管理系统如何借鉴 |
|---------|--------------|-------------------|
| **统计卡片** | 顶部5个指标卡片 | 每个子网段顶部显示：总数/空闲/占用 数量统计 |
| **颜色语义** | 绿=完成、红=异常 | 绿=空闲IP、红/橙=占用IP，直观区分 |
| **搜索框** | 支持多字段模糊搜索 | IP/使用人/部门/MAC 全局搜索 |
| **Tab 导航** | 看板视图/制定计划/验收实绩 | 子网段 Tab 切换 |
| **分组展示** | 表格按区分→班组分组 | 网格按子网段分组展示 |
| **整体风格** | 简洁专业、信息密度高 | 采用相似的卡片式布局和配色 |

### 4.2 不适合直接照搬的

| 参考系统特点 | 原因 |
|------------|------|
| 表格展示方式 | IP管理用网格(Grid)更直观，255个IP一览无余 |
| 复杂图表仪表盘 | IP管理数据维度简单，不需要饼图/趋势图 |
| 多页 HTML 文件结构 | IP管理是单页应用(SPA)即可 |
| Excel 直读模式 | IP需要频繁增删改，数据库更合适（见下方分析） |

### 4.3 关于数据存储方式的思考

参考系统疑似采用"前端直读 Excel"模式，这对于**只读展示**场景（生产日报看板）是可行的。但 IP 管理系统有本质区别：

| 对比项 | 生产日报看板 | IP管理系统 |
|--------|-----------|-----------|
| 数据操作 | 只读展示为主 | 频繁占用/释放/编辑 |
| 并发场景 | 单人制定、多人查看 | 多人同时操作 |
| 数据一致性 | 低要求（日报级别） | 高要求（避免重复分配） |
| 实时性 | 按天更新 | 操作即时生效 |

**结论：IP管理系统仍建议使用 SQLite 数据库**，原因：
1. Excel 文件锁 — 多人同时写入会冲突
2. 原子操作 — 数据库保证占用/释放不会冲突
3. 查询性能 — 搜索 2040 条记录，数据库远快于每次解析 Excel
4. 数据安全 — 数据库支持事务，不会因意外中断导致文件损坏

> Excel 仅作为初始数据导入源和导出备份格式。

## 五、综合建议

取参考系统之长，结合 IP 管理的特点，最终方案：

1. **统计卡片** — 借鉴顶部统计栏设计，展示当前网段的空闲/占用/总数
2. **颜色系统** — 借鉴颜色语义，空闲绿色、占用橙色，状态一目了然
3. **搜索功能** — 借鉴多字段搜索框，支持 IP/人名/部门模糊搜索
4. **核心差异** — 用网格(Grid)替代表格(Table)作为主展示方式，更适合 IP 段的可视化
5. **数据层** — 不照搬 Excel 直读，采用 SQLite 保障数据一致性和操作安全性
